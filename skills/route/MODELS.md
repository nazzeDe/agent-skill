# 子代理模型选型参考（Model Routing）

当所处 harness 支持为 `subagent` 指定模型（如 `model` 参数）时，主控编排 Agent 按本文件的**模型家族特征**与**任务路由矩阵**，从当前环境可用模型列表中匹配具体的 `provider/model-id`。

## 各模型家族优缺点分析

### 1. GPT 系列（高推理 / 编码系）
* **核心长项**：深度逻辑推演、第一性原理抽象、**后端开发**（复杂业务逻辑、数据建模、并发控制、系统接口设计）、严密逻辑审查与边界缺陷排查。
* **主要短板**：前端视觉表现与 UI 交互细节不及 Claude 与 Kimi；高推理档位耗时较长。
* **适用定位**：**后端开发主力**、**`skeleton`（类型与接口签名设计）**、**`refine` / `Ambiguity Gate`（代码减法与规约审查）**。

### 2. Claude 系列（Opus / Sonnet）
* **核心长项**：**前端开发长项**（复杂组件架构、UI/UX 细节、状态与交互）、**长周期/多步骤复杂任务（Long-horizon tasks）执行稳定**、跨多文件连续工具调用与静态门禁修复能力强。
  * **Opus 档**：擅长跨模块全局架构与复杂权衡；
  * **Sonnet 档**：兼顾编码速度、指令遵循与长链路稳定性。
* **主要短板**：Token 成本较高，用于局部微小改动的性价比低。
* **适用定位**：**长周期/中大型任务主力**、**复杂前端开发**、**多模块跨文件重构与门禁闭环**。

### 3. Kimi 系列（Kimi for Coding / k 系列）
* **核心长项**：**前端开发长项**、响应速度快、对边界清晰的局部编码指令执行精准、性价比高。
* **主要短板**：超长周期、跨多模块或需要在长链路中反复调试修复的复杂任务，稳定性不及 Claude。
* **适用定位**：**小型/轻量前端任务主力**（单组件实现、局部样式与交互调整、小型页面改动、UI 原型 `prototype`）及局部轻量修改。

### 4. Gemini 系列（Pro / Flash）
* **核心长项**：**日常聊天、自然语言写作、文本润色**、头脑风暴与长文档归纳。
* **主要短板**：具体工程实现（生产代码编写、多步工具链操作、静态门禁修复）的精准度与代码质量不及 GPT / Claude / Kimi。
* **适用定位**：仅用于**对话沟通、需求文案撰写、文档/Issue 整理**；**所有具体编写代码、编写测试、运行静态门禁与代码审查的工程子代理任务，均交由 GPT、Claude 或 Kimi 执行**。

### 5. DeepSeek / 极速轻量模型（Flash 档）
* **核心长项**：吞吐极快、成本极低，适合高频只读检索。
* **主要短板**：深层架构抽象与复杂多步代码修改能力有限。
* **适用定位**：**`scout` 只读检索**（代码库搜索、定位文件、查证环境事实）。

## 任务特征 $\to$ 模型选型矩阵

派发子代理前，按**工作流阶段 + 领域（前/后端）+ 任务规模**三个维度选定目标模型家族，并映射为当前 harness 中已启用的具体模型 ID：

| 任务阶段 / 类型 | 细分场景与任务特征 | 首选模型家族 | 备选模型家族 |
| :--- | :--- | :--- | :--- |
| **`scout`** | 只读检索代码库、查证文件与环境事实 | **DeepSeek (Flash)** | Kimi |
| **`Ambiguity Gate`** | 独立上下文需求多义性与未定义边界审查 | **GPT（高推）** | Claude Opus |
| **`skeleton`** | 定位上游根因修改点、定义数据结构与跨模块接口签名 | **GPT（高推）**（偏后端/算法）<br>**Claude Opus**（偏前端/全栈架构） | Claude Sonnet |
| **`contract`** | 编写高密度表驱动失败契约测试（Failing Tests） | **GPT**（后端逻辑/接口测试）<br>**Claude Sonnet**（复杂前端/长链路测试）<br>**Kimi**（小型前端组件测试） | Claude Sonnet / GPT |
| **`work` — 后端** | 后端业务逻辑、数据库/API、并发与底层算法实现 | **GPT** | Claude Sonnet |
| **`work` — 前端（中大型/长周期）** | 多组件联动、复杂状态机、长链路前端工程任务 | **Claude（Sonnet / Opus）** | GPT |
| **`work` — 前端（小型/局部）** | 单组件开发、样式修复、局部交互微调、轻量前端任务 | **Kimi** | Claude Sonnet |
| **`work` — 跨模块长周期任务** | 涉及多文件协同、长耗时持续修复并通过 `./scripts/gate` | **Claude（Sonnet / Opus）** | GPT |
| **`refine` — 减法与规约** | `Subtraction`（消除冗余补丁）、`Spec Fidelity`、`Test SNR` | **GPT（高推）** | Claude Opus |
| **`refine` — 代码品味** | `Taste & Comment`（微观代码品味与注释审查，前端优先 Claude，后端优先 GPT） | **Claude Sonnet / Opus** 或 **GPT** | 异构交叉审查（与 `work` 模型错开） |
| **`prototype`** | 快速生成单文件 HTML 交互/视觉原型 | **Kimi**（轻量快速）或 **Claude Sonnet**（复杂状态） | GPT |
| **聊天与写作** | 自然语言对话、润色说明文本、撰写总结 | **Gemini** | Claude / GPT |

## 选型执行准则

1. **环境对齐**：调用 `subagent` 传入 `model` 前，确保使用当前 harness 合法的 `provider/model-id` 格式（若不确定可用列表，先通过工具提示或配置查询获取当前环境支持的模型名，不臆造模型 ID）。
2. **异构审查优先**：在 `refine` 阶段派发 `reviewer` 时，优先选择与 `work` 阶段不同家族的模型（例如 GPT 编写后端代码 $\to$ Claude 审查品味；Kimi 编写小型前端 $\to$ Claude 或 GPT 审查减法与规约），避免同源模型的检验盲区。
