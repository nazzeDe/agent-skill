# 最小实现与静态硬门禁（Work）

在已锁定的类型骨架与契约测试之内填充实现代码，并强制跑通所有确定性静态检查工具。本阶段未通过静态门禁前，严禁退出或进入审查阶段。

## 遵守锁骨铁律（Skeleton Discipline）

* **只填肉，不改骨**：严格在 `skeleton` 阶段锁定的公共类型定义与函数签名内部编写实现。**严禁私自修改跨模块公共类型、结构体字段或函数签名**（这在多 Worktree 并行执行时是防止局部最优冲突的绝对红线）。
* **异常熔断上报**：若在实现过程中发现已锁定的类型签名存在根本性缺陷、不靠丑陋补丁就无法实现，**立即停止编写代码**，向主控/调用方报告具体的签名缺陷与修改建议，绝不在局部硬凑绕行逻辑。
* **完成判据**：所有实现均位于被分配的模块边界内，跨模块公共契约未被篡改。

## 编写最小无噪实现（Minimal Implementation）

* **最小编辑原则**：只写让契约测试与排错探针变绿（Green）所需的最小逻辑。优先使用标准库组合子与纯函数变换，避免手写带可变游标的循环状态机。
* **零衍生噪音（No Garnish）**：
  * 严禁添加需求未要求的配置项、兜底分支、未被调用的辅助函数或额外 UI 缀饰。
  * 严禁残留任何分步解说式注释（如 `// Step 1`）、被注释掉的旧代码或复述签名的文档注释；若确需注释，必须同时通过 `docs/agents/comment-guidelines.md` 的三问判据。
* **脚手架清理**：若实现过程中为了调试复杂算法临时添加了打印语句或仅测内部实现步骤的脚手架测试，在逻辑跑通后当场清理干净。
* **完成判据**：业务功能已实现，无任何未请求的附加逻辑或注释噪音。

## 静态硬门禁自愈循环（Static Gate Loop）

实现完成后，立即执行项目的确定性静态门禁：
* **优先执行项目门禁脚本**：若存在 `./scripts/gate`（或 `AGENTS.md` 中声明的 Static gate 命令），直接运行它。
* **默认回退门禁序列**（当项目尚未运行 `/init-project` 生成 `./scripts/gate` 时，依次运行）：
  * 编译与类型检查 + 项目 Linter（将 warnings 视为 errors）；
  * 全量测试套件；
  * 纯圈复杂度检查：`/home/nazze/Studio/oss/unclebob/crapper/crapper --no-coverage --changed --threshold 10`；
  * 结构重复度检查：`/home/nazze/Studio/oss/unclebob/dryer/dryer`。
* **自愈修复**：
  * 若圈复杂度超标（`CC > 10`）：通过化简条件分支、利用上游契约删除多余防御分支或提取内聚纯函数来降维。
  * 若结构重复度超标（`>= 0.8`）：抽取共享变换逻辑（包含测试代码中的重复 Setup），确保同一决策只在一处存在。
  * 每次修改后重新运行完整静态门禁，直至退出码为 `0`。
* **完成判据**：静态门禁命令完整跑通且退出码为 `0`。
