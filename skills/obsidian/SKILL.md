# Obsidian Vault

目标：保护个人知识复用。结构、命名、链接、正文整理都服务未来再次理解、查找、迁移和行动。

笔记地址为`~/Documents/obsidian-note`

## 目录映射
`_moc.md`=**领域导航**,不担任其他职责。
`_sources/`=待消化知识素材。
`_sources/_records/`=已处理且有留存价值的素材。
`misc/`=用户杂项；Agent 默认只识别入口。

按需读：
- 候选 `_moc.md`
- 必要相邻笔记

此SKILL.md作为路由入口。根据用户目标读下列文件获得详细信息:
- 笔记库结构调整读：[organize-structure.md](organize-structure.md)。
- 正文整理读：[note-style.md](note-style.md)。
- 对话学习读：[teach.md](teach.md)。
- 对话/素材提取为笔记读：[conversation-note.md](conversation-note.md)。

## 总流程

1. 判复用目标：未来在哪个问题、任务、领域中打开它。
2. 判材料角色：可复用知识、可复用方法、速查、过程记录、导航、原始素材。
3. 判操作边界：学习型材料可消化；维护型材料保护原始语境。
4. 整理路径、命名、链接、MOC、素材层。
5. 整理正文。
6. 更新受影响的 `[[...]]` 链接。
7. 报告已做、保留、建议。

## 操作边界

可主动改：
- 可复用知识：概念、模型、判断、关系、反例。
- 可复用方法：判断、步骤、工具边界、例外。
- 明显临时文件名、明显错放路径、低风险链接维护。

谨慎改：
- 速查：保高密度结构，只清外壳。
- 过程记录：保时间线、原始判断、证据链。
- 导航页：只维护链接和分组。
- 原始素材：归档、引用；提取规则见 `conversation-note.md`，保可复查性。

先建议再改：
- 可能破坏外部引用、项目约定的移动/重命名。
- 大规模重组。
- 删除素材。

## 写作原则

以帮助用户更好理解知识为首要目标。
删除管理痕迹、套话和 agent 作业流水，只保留有学习价值的内容。

## Obsidian 语法
- 库内笔记：用 `[[笔记名]]`
- 库内笔记但标题不适合直接显示：用 `[[笔记名|显示文字]]`
- 表格单元格里使用别名链接时必须转义：`[[note-name\|显示文字]]`
- Mermaid 中节点文本含 `|`、`[`、`]`、`:` 等符号时给节点标签加引号
- 文件名或路径中有空格时，Markdown 文件链接用尖括号包住目标
- 外部网页来源：用 `[标题](URL)`
- 附件或图片：用 `![[文件名]]`
- 精确引用某节：用 `[[笔记名#标题]]`
- 凡是表达抽象形式关系的内容，用 LaTeX 数学块 $...$(行内表达式,表示下标/形式元符号时使用) 或 $$...$$(块级表达式)。
- 凡是需要按原样复制、保留缩进或表示具体文本样例的内容，用代码块。
- 表格用于对照、映射和结果汇总。
- 使用svg画图：```svg\n ```
