# 对话与素材转笔记

目标：把学习对话或用户提供的素材压缩成客观、可复用的知识笔记。

## 原则

保留有价值内容。删除聊天流水、话术、鼓励、过程反馈。

只写客观知识：
- 概念
- 判断
- 机制
- 条件
- 边界
- 例子
- 反例
- 容易混淆的点

## 提取

把对话互动转成知识结构：
- 练习暴露的边界 -> 判断边界
- 推理过程 -> 为什么 —— 使用户知其所以然
- 答错点 -> 容易混淆的点
- 追问形成的新概念 -> 独立笔记或小节
- 教学顺序 -> 只在有助于理解时保留

把 source/素材转成知识结构：
- 原文观点 -> 可复用判断
- 原文步骤 -> 可执行方法
- 原文案例 -> 例子或反例
- 原文证据 -> 支撑判断的来源
- 临时摘录 -> 正式笔记正文
- 混合笔记中的独立问题 -> 独立笔记或小节

保留原始语境。不要把来源改写到无法复查。

拆分 source 的条件：
- 回答独立问题。
- 可独立链接。
- 未来会单独打开。
- 有清晰标题。

轻微跑题留在原笔记，用小节整理。

拆分后用自然链接连接原笔记、新笔记和来源。

写客观表达：
- `X 与 Y 的区别是...`
- `判断边界：...`
- `适用条件：...`
- `反例：...`

## 拆分

按可复用问题拆，不按对话轮次拆。

默认一篇。出现独立问题时拆多篇并互链。

大主题可生成 `_moc.md` 或建议建立问题地图。

## 来源

只在来源本身有复查价值时才链接：
- 官方文档
- 论文
- 原文
- 高价值已有笔记
- `_sources/` 中保留的原始素材

## 写入

用户要求写入 vault 时：
1. 确定未来复用场景。
2. 选择路径和文件名。
3. 生成或更新笔记。
4. 需要保留 source 时归档到 `_sources/_archive/`；未处理 source 暂放 `_sources/`；否则只保留必要来源链接。
5. 更新必要链接和 MOC。
6. 报告已做、保留、建议。
